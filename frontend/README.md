### 1. User and Group Management

To begin, I set up a collaborative environment on the server. My first step was creating a shared group to manage permissions efficiently.

### 2. Secure SSH Access Configuration

To provide secure, passwordless access to the server, I configured SSH key-based authentication for each user. After receiving their public SSH keys, I performed the following steps for each account.

First, I created the necessary `.ssh` directory and `authorized_keys` file in the user's home directory.

**Example for brown-wangeci**

```bash
sudo mkdir -p /home/brown-wangeci/.ssh
sudo touch /home/brown-wangeci/.ssh/authorized_keys
```

Then, I added their public key to the `authorized_keys` file which their generated by running the command.

```bash
ssh-keygen -t rsa -b 4096
```

```bash
echo 'ssh-rsa AAAA...' | sudo tee -a /home/brown-wangeci/.ssh/authorized_keys
```

Finally, I set strict permissions on the directory and file to ensure security.

```bash
sudo chown -R brown-wangeci:brown-wangeci /home/brown-wangeci/.ssh
sudo chmod 700 /home/brown-wangeci/.ssh
sudo chmod 600 /home/brown-wangeci/.ssh/authorized_keys
```

After repeating this process for all users (sharlet and deborah), they could securely log in via `ssh <username>@ip-address`.

### 3. DNS and Domain Configuration

My project's domain, `viscerealplate.me`, is registered at Namecheap, and the server is a DigitalOcean droplet. To connect them, I first updated the nameservers at Namecheap to point to DigitalOcean.

*   `ns1.digitalocean.com`
*   `ns2.digitalocean.com`
*   `ns3.digitalocean.com`

Next, inside my DigitalOcean control panel, I created an **A record** to point the subdomain `ics-project.viscerealplate.me` to my server's IP address.

<img width="1272" height="691" alt="image" src="https://github.com/user-attachments/assets/ed78ebf3-457f-4453-aa45-d187bf6d5cb3" />

### 4. Project Directory and Permissions Setup

With the domain configured, I created the web root directory for the project on the server.

```bash
sudo mkdir -p /var/www/ics-project.viscerealplate.me
```

To allow the team to work in this directory, I changed its group ownership to the `server-admin-group`.

```bash
sudo chown -R :server-admin-group /var/www/ics-project.viscerealplate.me
```

I then set permissions to allow the group members full read, write, and execute access. The `setgid` bit ensures any new files or folders created inside this directory automatically inherit the group ownership.

```bash
sudo chmod -R 775 /var/www/ics-project.viscerealplate.me
sudo chmod g+s /var/www/ics-project.viscerealplate.me
```

### 5. Firewall Configuration (UFW)

As a final security measure, I configured the Uncomplicated Firewall (UFW). I started by setting the default policy to deny all incoming traffic, ensuring only explicitly allowed connections can get through.

To maintain my own access, I allowed SSH connections.

```bash
sudo ufw allow ssh
```

To make the web project accessible, I opened the standard HTTP and HTTPS ports.

```bash
sudo ufw allow http
sudo ufw allow https
```

With the rules in place, I enabled the firewall.

```bash
sudo ufw enable
```

**Nginx Configuration**

```bash

    listen 80;
    server_name ics-project.viscerealplate.me;

    root /var/www/ics-project.viscerealplate.me/ICS-Project-I/frontend/build;

        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

## 🔧 Server Administration & Deployment Guide

The following steps outline the manual server administration and deployment process used for this project.

### 1. Server Setup (Infrastructure)
1.  Provision a cloud server (e.g., DigitalOcean, AWS) with **Ubuntu 22.04**.
2.  Log in via SSH and update the system:
    ```bash
    sudo apt update && sudo apt upgrade
    ```
3.  Install Nginx (web server) and Git (version control):
    ```bash
    sudo apt install nginx git
    ```
4.  Install and configure the **Uncomplicated Firewall (UFW)**:
    ```bash
    sudo apt install ufw
    sudo ufw allow ssh  # Or 22/tcp (CRITICAL: Do this first)
    sudo ufw allow http # Or 80/tcp
    sudo ufw allow https # Or 443/tcp
    sudo ufw enable
    ```

### 2. DNS Configuration
1.  Purchase a domain name (e.g., from Namecheap).
2.  In the registrar's DNS settings, create two records:
    * **'A' Record:**
        * **Host:** `@`
        * **Value:** The server's Public IP Address.
    * **'CNAME' Record:**
        * **Host:** `www`
        * **Value:** `@` (or your domain name)

### 3. SSL & Nginx Configuration

1.  **Install Certbot and the Nginx Plugin:**
    First, install the necessary software on the server. The `python3-certbot-nginx` package integrates Certbot directly with Nginx, allowing for full automation.
    
    ```bash
    sudo apt install certbot python3-certbot-nginx
    ```

3.  **Obtain and Install the SSL Certificate:**
    Run the Certbot command, specifying the Nginx plugin. Certbot automatically reads your Nginx configuration files, finds the domain, and guides you through the setup.
    
    ```bash
    sudo certbot --nginx
    ```

5.  **Follow the On-Screen Prompts:**
    *   Certbot will ask you to select the domain to activate HTTPS for.
    *   It will then ask if you want to redirect all HTTP traffic to HTTPS. **It is strongly recommended to choose this option** to enforce a secure connection for all users.

    Upon completion, Certbot automatically modifies your Nginx server block to include the SSL certificate and reloads Nginx to apply the changes.

6.  **Verify Automatic Renewal:**
    Certbot also sets up a systemd timer that automatically renews the certificate before it expires. You can verify that the renewal process works correctly by running a dry run:
    ```bash
    sudo certbot renew --dry-run
    ```

### 4. Application Deployment
1.  Log into the server via SSH.
2.  Clone the secured application code from the private GitHub repository into the Nginx web root:
    ```bash
    git clone your_repo_link /var/www/yourproject
    ```
3.  Install application dependencies, build the React frontend (`npm run build`), and start the Node.js backend (e.g., using a process manager like `pm2`).
4.  Update this README with the final live URL.

## 🛡️ Security Measures Implemented

* **Firewall (UFW):** The server is protected by UFW, only allowing traffic on essential ports (SSH, HTTP, HTTPS).
* **SSL/TLS (HTTPS):** A certificate from ZeroSSL is installed, and Nginx is configured to enforce HTTPS-only connections, encrypting all traffic.
* **Password Hashing (bcrypt):** The application code was modified to use `bcrypt` for hashing all user passwords, preventing them from being stored in plaintext.
* **Input Validation:** Client-side HTML5 validation (e.g., `required`, `type="email"`, `minlength="8"`) was added to forms to improve data integrity and user experience.
